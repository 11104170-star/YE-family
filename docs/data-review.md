兩支系沒有具名共同祖先或明確血緣證據，不建立共同祖先實體，也不因 PDF 左側共用裝飾線就將兩支系相連。版面中的「堂上歷代始高曾祖」是標題，不作人物。

關係的 `status: source-supported` 表示**原文支持此層級**，不是外部史料已驗證的生物血緣；`status: user-confirmed` 表示家族使用者明確確認；`status: pending` 代表待考證。PDF 關係保留來源頁碼，家族補充則保留確認日期、確認 ID 與原意說明，不偽造 PDF 頁碼。尚未明確確認父／母角色的關係仍以 `parentIds` 保存，`fatherId`、`motherId` 保留 null。不從「傳女」、姓名或配偶關係推定父母、性別或共同子女。

## 驗證方式

`node scripts/validate-data.mjs` 驗證重複 ID、懸空引用、配偶對稱、親屬邊與人物欄位一致性、證據狀態、世代、祖先循環、自身親屬、祖先婚姻衝突、支系與照片路徑。可能在世人物的完整出生日期會被拒絕，請僅登錄年份；公開 JSON 本身必須先去除敏感資料。

`node --test tests/*.test.js` 涵蓋跨頁／跨行、獨立支系、同名與別名、照片不同高度、所有卡片不重疊、分支收合不改原資料、多位配偶與雙親引用等情境。這些檢查能攔截結構問題；新增史料或更正親屬仍需家族核對原始證據。
